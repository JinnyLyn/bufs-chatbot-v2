# BUFS 챗봇 QA 평가셋 (100문항) — 완성본

학사 안내 RAG 챗봇 평가용 100문항 데이터셋. 비어 있던 **Gold Chunk ID / Retrieval
Success / Generation Success** 3개 컬럼을 채우고, KB에 근거가 없거나 사실이 틀린 행을
수정했다. 채점은 **실제 운영 챗봇(localhost:8000)에 100문항을 그대로 질의**해 받은
답변·검색결과로 했다 (2026-06-26 실행, `X-Test-Mode`로 로그 제외).

## 결과 요약

| 지표 | 결과 |
|---|---|
| **Retrieval Success** | **75 / 100 (75%)** |
| **Generation Success** | **27 / 100 (27%)** |

카테고리별:

| 카테고리 | n | Retrieval | Generation |
|---|--:|--:|--:|
| 수강신청 | 20 | 20/20 | 4/20 |
| 성적 | 15 | 9/15 | 3/15 |
| 휴학 | 15 | 9/15 | 4/15 |
| 졸업 | 15 | 13/15 | 4/15 |
| 복학 | 10 | 8/10 | 3/10 |
| 등록금 | 10 | 6/10 | 4/10 |
| 전과/복전 | 6 | 5/6 | 1/6 |
| 기타 | 6 | 5/6 | 4/6 |
| 학적 | 3 | 0/3 | 0/3 |

> **핵심 관찰**: 검색은 75%로 문서를 잘 찾지만, 생성은 27%에 그친다. 즉 병목은
> 검색이 아니라 **생성/종합**이다. 특히 성적·휴학·복학·학적처럼 근거가 문서에 흩어져
> 있거나 얇은 시나리오형 질문에서 챗봇이 "제공된 자료에서 찾지 못했습니다"식으로
> 보수적으로 거부하거나(예: 27·39·49·60·70), 엉뚱한 메뉴/날짜를 답한다(예: 22·24·82·92·93).

## 채점 기준

- **Retrieval Success (문서 단위)**: 정답이 담긴 KB 문서가 챗봇의 검색결과(`results`의
  source)에 포함되면 O. Gold Document의 친화명을 실제 KB 파일로 매핑하고, 모호하거나
  잘못 지정된 경우(`학사공지`, `장학공지`, 휴·복학인데 공인결석 매뉴얼로 잘못 지정 등)는
  답을 실제로 담은 문서로 교정해 판정.
- **Generation Success (의미 단위·수작업)**: 키워드 단순매칭은 동의어("제외"↔"포함되지
  않습니다")로 인한 누락과 짧은 토큰("전 학년"이 "전공"+"학년"에 오매칭)으로 인한 과대평가가
  모두 커서 신뢰할 수 없었다. 따라서 **100개 답변을 모두 읽고**, 기대답변의 핵심을 사실
  오류 없이 전달하면 O로 판정했다(부분적이라도 방향이 맞고 거부가 아니면 O).
- **Gold Chunk ID**: 정답을 담은 KB 문서(`resolved_kb_doc`)에서 must_include 앵커를 가장
  많이 포함하는 parent 청크의 ID(예: `2026학년도1학기학사안내_parent_31`). 부모/자식
  계층 청킹의 parent 저장소(`parent_store/`) 식별자 그대로다.

## 데이터셋과 챗봇이 안 맞아 수정한 행 (4건)

honest-eval 원칙(사용자 선택)에 따라 **KB에 근거가 없거나 사실이 틀린 행만** 고쳤다.
챗봇이 단지 약해서 틀린 행은 그대로 FAIL로 남겼다.

| id | 문제 | 수정 |
|---|---|---|
| 14 | 기대답변이 "3·4학년이 1·2학년보다 **먼저** 신청"이라 했으나, 학사안내 일정표상 **1학년이 먼저**(2.9→2.10→2.11→2.12) → 방향 오류 | 기대답변/키워드를 "별도 우선권 없음·학년별 일정"으로 정정 |
| 56 | 기대답변의 "비밀번호 찾기" 셀프 기능이 KB에 없음 | "학사지원팀 문의로 재설정"으로 재근거화 |
| 74 | "인터넷 증명발급(영문 졸업예정증명서)" 서비스가 KB에 없음 | "담당부서 문의"로 재근거화 |
| 97 | "인터넷 증명발급(재학증명서)" 서비스가 KB에 없음 | "담당부서 문의"로 재근거화 |

> 참고: KB에 정답 근거가 분명히 있는데 챗봇이 못 찾은 행(예: 7번 재수강 성적취소 3/4선,
> 91번 계열별 등록금)은 **수정하지 않고 FAIL 유지** — 평가셋으로서의 의미를 지키기 위함.

## 산출물

- **`qa_completed.csv`** / **`qa_completed.md`** — 완성된 100문항 표 (모든 컬럼 채움).
- `qa_completed.json` — 위와 동일 데이터(JSON).
- `qa_dataset.json` — 원천 데이터셋(4건 수정 반영).
- `live_runs.jsonl` — 챗봇 실제 답변·검색결과 원본(감사용). **생성물이라 커밋 제외**
  (`.gitignore`) — `python qa/run_live.py`로 재생성.

## 재현

```bash
python qa/run_live.py        # 100문항 → 챗봇 질의 (백엔드 :8000 필요)
python qa/build_final.py     # 채점·수정 적용 → CSV/JSON + 요약
python qa/to_markdown.py     # MD 표 렌더
```
