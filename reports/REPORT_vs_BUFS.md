# 비교 보고서 — 신규 agentic-RAG 챗봇 vs 기존 BUFS-CHATBOT

> 작성: 2026-06-08 · 동일 테스트셋(combined88) · 동일 채점기·동일 RAGAS judge(exaone) 기준의 공정 비교

---

## 1. 두 시스템 개요

| | **신규 (agentic-RAG)** | **기존 BUFS-CHATBOT** |
|---|---|---|
| 검색 전략 | **agentic 멀티스텝** (LangGraph: 검색→parent보강→압축→종합, 반복) | 단일패스 하이브리드 + **리랭커 + 학사 그래프(AcademicGraph)** |
| 벡터DB | Qdrant (dense `bge-m3` + BM25, RRF) | ChromaDB (`bufs_v2`) + BM25 + `bge-reranker-v2-m3` |
| 지식베이스 | **23문서**(엄선) / 1,459청크 | **~69출처**(공지 크롤링·FAQ·성적표 등 대규모) |
| LLM | qwen3.5:9b (H100) | qwen3.5:9b / gemma / exaone 등 (LM Studio·Ollama·H100) |
| 제품범위 | **핵심 챗 only** (관리자·성적표·FAQ 제외) | 관리자·학업성적사정표·FAQ·공지크롤러 포함 **풀 제품** |
| 배포 | Cloudflare 터널 → 로컬/H100 | Docker(nginx+frontend+backend) |

> 설계 철학: 신규 = **가볍고 정밀한 agentic + 엄선 KB**, 기존 = **무거운 파이프라인 + 대규모 크롤링 KB + 그래프**.

---

## 2. 룰기반 비교 (combined88, 동일 채점기)

| 지표 | 신규 (속도구성/정확도구성) | **기존 BUFS** | 승 |
|---|---|---|---|
| **contains 정답률** (81) | **85.2% ~ 91.4%** | 80.3% (65/81) | 🟢 **신규** |
| **문서밖 거부율** (8) | **100% (8/8)** | 50% (4/8) | 🟢 **신규 (할루시네이션 적음)** |

- 신규는 두 구성 모두 기존을 상회. 특히 **문서밖 질문 거부**에서 압도(8/8 vs 4/8) — 작은 KB라도 모르는 건 정직하게 거부.

## 3. RAGAS 비교 (동일 judge=exaone 계열, 공정 비교)

| 지표 | 신규(속도/정확도) | 기존 BUFS | 승 |
|---|---|---|---|
| Faithfulness 성실성 | 0.84 / 0.86 | **0.93~0.94** | 🔵 기존 |
| Answer Relevancy 관련성 | 0.78 / 0.83 | 0.81~0.83 | ⚖️ 비슷 |
| **Context Precision 정밀도** | **0.63** | 0.40~0.42 | 🟢 **신규 (+0.22)** |
| Context Recall 재현율 | 0.68 | **0.77~0.78** | 🔵 기존 |
| Answer Correctness 정확도 | 0.58 / 0.62 | **0.69~0.78** | 🔵 기존 |
| **종합 AVG** | 0.70 / 0.72 | 0.73~0.74 | ⚖️ **사실상 동률** |

> RAGAS 절대점수는 judge 의존(같은 bufs 데이터도 gemini-2.5-flash judge면 0.42~0.62). exaone끼리만 비교함.

**해석**: 종합은 대등. **신규는 검색 정밀도(노이즈 적음)에서 압도**(parent/child + 학번·월 청킹 효과), **기존은 대규모 KB로 재현율·성실성·정확도가 높음**(근거를 더 많이·완전하게 검색).

## 4. 검색 품질 비교

| | 신규 | 기존 BUFS |
|---|---|---|
| Context Precision | **0.63** | 0.41 |
| Context Recall | 0.68 | **0.78** |
| retrieval recall@5 | (멀티스텝, 측정방식 상이) | 0.79 |

- **신규(정밀)**: 적게 가져오되 관련도 높음 → 노이즈로 인한 LLM 거부 적음.
- **기존(재현)**: 많이 가져와 근거 누락 적음 → 단, 노이즈로 정밀도 낮음.
- 근본 원인 = **KB 크기**(23 vs 69출처). 신규의 recall 약점은 문서 추가로 개선 가능.

## 6. 강점 / 약점 요약

### 신규 agentic-RAG
- 🟢 **강점**: 룰기반 정확도·문서밖 거부·검색 정밀도·속도 우위. 가벼운 인프라(Docker 불필요). 학번·날짜 표 정확성(전용 청킹).
- 🔴 **약점**: KB가 작아 재현율↓. 비슷한 표 값 중 정확한 행 선택 정밀도(생성오류 10%). 공유 H100 의존.

### 기존 BUFS-CHATBOT
- 🟢 **강점**: 대규모 크롤링 KB로 재현율·정답 완성도↑. 리랭커·학사그래프로 근거 풍부. 관리자·성적표·FAQ 등 **제품 기능 풍부**.
- 🔴 **약점**: 문서밖 거부 약함(4/8, 할루시네이션). 검색 정밀도 낮음(노이즈). 무거운 파이프라인(지연·운영비).

## 7. 결론

| 관점 | 우위 |
|---|---|
| 룰기반 정답률 / 거부 신뢰성 | **신규** (85~91% / 8·8, vs 80% / 4·8) |
| RAGAS 종합 | 대등 (0.70~0.72 vs 0.73) |
| 검색 정밀도 | **신규** |
| 검색 재현율·성실성·정답완성도 | **기존** |
| 속도·배포 단순성 | **신규** |
| 제품 기능 폭 | **기존** |

> **신규 챗봇은 엄선된 23문서 + 로컬/H100 9B로, 대규모 크롤링·리랭커·그래프를 갖춘 기존 BUFS-CHATBOT과 핵심 학사 QA에서 대등하거나 앞선다.** 특히 **정확도·거부 신뢰성·검색 정밀도·속도**에서 우위. 기존의 우위(재현율·정답 완성도)는 본질적으로 **KB 규모** 차이이므로, 신규에 문서를 더하면 좁혀진다.
>
> **권장**: 신규를 기본 서비스로(빠르고 정직), 정밀 답변이 중요한 영역은 KB 확충 + (선택) 리랭커 도입으로 재현율 보강.
